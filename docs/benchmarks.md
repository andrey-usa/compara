## Versions

compara built from the run's commit (compara 0.7.0); DuckDB 2.0.0 and Polars 2.1.0 installed from PyPI at their latest in the run, on Python 3.13.18. qsv 29.0.0 is its release binary, as downloaded in the run.

## Method

Each pair is written by `compara-gen-data` (seed 7) in each format, and every tool reads the same files. Before each run the files that tool reads are put in a stated page-cache state: warm, read to the end just before the run; cold, dropped from the page cache (`posix_fadvise` DONTNEED), so the tool reads them from the runner's disk. The state is set for every tool alike, so no tool starts warmer because of what the one before it did (in runs before this was done, a tool killed for memory left the next one's inputs evicted: compara's 10M-row CSV took 0.70 s in one round and 9.33 s in the next, run 44629611468). Each run records the share of its inputs in the page cache as it starts and its major page faults. Each round also times reading both inputs from a cold cache, the least any tool's cold run can take. Each tool runs in a process of its own; CPU time and peak RSS are that process's (`wait4`). Peak RSS counts the pages of files a tool maps, which the kernel can drop and read again under memory pressure: compara maps both inputs, so most of its RSS is the files themselves. The private part is the tool's own memory (heap, stacks; `RssAnon` of its process tree, sampled every 5 ms, so a lower bound), what a container limit has to leave it. Each tool computes what compara does: values compared as text in CSV and by value in Parquet, an empty field equal only to an empty field, and a key that appears twice in a file compared by its first row. DuckDB reads Parquet where it is (`read_parquet`, its row numbers from the file) and loads each CSV into a table once, for a row order to take the first row by; Polars runs its lazy API, which its streaming engine did not beat. qsv diff reads CSV only, has no option to leave a column out and says its keys must be unique (these tables repeat a few): the ignored column is cut from both files with `qsv select` and each key's first row is kept with `qsv extdedup`, both before the timing and not charged to qsv, and the timed process is `qsv diff -k account_id,txn_id LEFT RIGHT` on every core, its output written to a file; the counts are read back from that output, and unchanged is the left file's rows (`qsv count`) less the changed and removed. The run fails unless every tool that finishes gives the same counts: 1M rows, CSV, 368 MB: 938,951 unchanged, 60,049 changed, 1,000 added, 1,000 removed; 1M rows, Parquet, 161 MB: 938,951 unchanged, 60,049 changed, 1,000 added, 1,000 removed; 10M rows, CSV, 3,679 MB: 9,390,680 unchanged, 599,320 changed, 10,000 added, 10,000 removed; 10M rows, Parquet, 1,609 MB: 9,390,680 unchanged, 599,320 changed, 10,000 added, 10,000 removed.

To run it yourself, from a checkout with compara built and `pip install duckdb polars`:

```sh
python3 scripts/bench_contenders.py --compara target/release/compara \
  --gen target/release/compara-gen-data --rows 1m,10m --json results.json
python3 scripts/gen_bench_docs.py results.json --page bench.md
```
